# Applying the analysis to a new library (procedure for coding agents)

Use this when the user says something like "do the hypothesis analysis for iris-lean with hypcheck". The user should not have to run any setup command; do every step yourself and report briefly. Ask only where marked **Ask**. Paths below are relative to the root of this repository (the directory that contains `tool/`). The workspace is always `workspaces/<name>/` (git-ignored); `libs/` holds only the published analyses and stays read-only.

1. **Find the repo.** If the user gave a path, use it. Otherwise look for an existing checkout next to this repository and in the user's usual source folders (also with/without `-lean`, `4` suffixes); if there is none, **Ask** where to clone it (default: next to this repository) and clone it (`git clone https://github.com/<org>/<repo>.git`; for a name without org, the usual homes are `leanprover-community/` and `leanprover/`). Never edit or commit in it afterwards.
2. **Find the Lake project.** `find <repo> -maxdepth 3 -name 'lakefile.*' -not -path '*/.lake/*'`. If there is one, use its directory. If there are several (iris-lean: `Iris/` without Mathlib, `IrisMath/` with Mathlib), pick the one matching what the user named or the largest library; if it is genuinely unclear, **Ask** with the candidates and their dependencies.
3. **Root module and scope.** The root module is the main `lean_lib` (`defaultTargets` in `lakefile.toml`, or `lean_lib` in `lakefile.lean`). Scope = the root module unless the user named folders (then `--modules A,B` below). Test and meta libraries stay out automatically when their module names don't start with the root.
4. **Build** (tell the user the expected time first: minutes for small libraries, 20–40 min without a cache):
   - Mathlib dependency (`grep -i mathlib lakefile.* lake-manifest.json`): `lake exe cache get` first.
   - `LEAN_NUM_THREADS=4 tool/template/scripts/capped --mem <min(60% RAM, MemAvailable − 2.5 GB)> -- lake build <Root>` (a systemd scope where available, uncapped otherwise; `capped --meminfo` prints total and available MB), in the background, watched for exit and memory kills.
   - Check `.lake/build/lib/lean/<Root>.olean` exists.
5. **Count:** `tool/hypcheck <lake-project-dir> <Root> [--modules …] --inventory-only`. It creates `workspaces/<name>/` (name: the project directory's name in lower case, or `--name`), builds the native tools with the library's toolchain (~1–2 min, ~3 GB), runs the self-test and counts the hypotheses in scope. If the self-test fails, fix the tool in `tool/` (see `tool/AGENTS.md`), not only the workspace copy.
6. **Mechanical stage:** tell the user the count and the expected time (measured: 338 hypotheses in 5 min with 3 workers, 487 in 7 min with 4; `tool/README.md` "What to expect"). For more than ~2,000 hypotheses, **Ask** before running. Then run the same command without `--inventory-only` (add `--private` to include private theorems) in the background and watch it; it resumes where it stopped. Report the summary from `workspaces/<name>/report.md`.
7. **Agent stage** (hand passes for the unresolved hypotheses): **Ask** first, with the open count and the cost model of `tool/PLAYBOOK.md` §4; agents cost money and time. With the user's go, read `workspaces/<name>/AGENTS.md` and `Plan.md` and execute the plan from P3b/P6a, asking again before every agent wave as the plan requires.

All workspace commands run from `workspaces/<name>` (the scripts refuse other directories). In later chats, "continue the <name> analysis" means: read `workspaces/<name>/Plan.md`; its Log says where things stand. Optional: `tool/link_repo.sh workspaces/<name>` writes a git-ignored `CLAUDE.local.md` into the library checkout so that Claude sessions opened there find the workspace.
